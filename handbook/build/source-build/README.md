# Source build

How a source tree becomes an installed shared library:
`configure`, the Makevars assembly, and the tarball round trip.

```sh
export MAKEFLAGS="-j$(nproc)"
R CMD INSTALL . --no-byte-compile
```

The first build compiles the whole vendored engine —
tens of minutes; an agent driving it must not cancel it.
An edit-test loop should not use this build at all:
[`fast-paths/`](/handbook/build/fast-paths/README.md)
turns the same command into seconds.

**Two stages.**
`R CMD INSTALL` runs `./configure` (`configure.win` on Windows),
then `make` in `src/` driven by `src/Makevars`.
`configure` computes no compiler flags;
it writes small include fragments
(`Makevars.rstrtmgr`, `Makevars.duckdb` or `Makevars.system-lib`),
deletes a stale `Makevars.system-lib` so a plain install can never
silently stay on the fast path,
and restores `src/duckdb/` from `src/duckdb.tar.xz` if the tree
arrived compressed — which is how a tarball built by
`R CMD build` compiles again under `R CMD check`.

**`.dd` files in `src/` stay in version control.**
They are dependency-tracking files generated by the
`%.dd: %.d` rule in `src/include/deps.mk`,
should include only local header files,
and should change _minimally_ only when local `#include` directives change.
A regeneration with system paths is spurious —
revert with `git checkout -- 'src/*.dd'`.
